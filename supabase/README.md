# إعداد قاعدة البيانات

1. طبّق ملفات migration الأربعة بالترتيب عبر Supabase CLI أو SQL Editor، وآخرها `20260827000400_reliability_and_payments.sql`.
2. أنشئ مستخدمي الإدارة والمطبخ في Supabase Auth.
3. اربط كل مستخدم بالمطعم في `store_members` مع دور `admin` أو `kitchen`.
4. أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` إلى بيئة النشر.

لا تستخدم مفتاح service role في المتصفح. إنشاء الطلبات العامة الجديد يتم عبر الدالة المحمية `create_order_v2`، والأسعار ورسوم التوصيل تُعاد حسابها من قاعدة البيانات.

الترحيل الثالث يضيف مناطق التوصيل والرسوم والتتبع العام ومؤقتات المطبخ وملفات العملاء والفواتير والإضافات المدفوعة. طبّقه بعد ترحيل White‑Label وقبل تفعيل الأقسام التجارية الجديدة.

الترحيل الرابع يضيف منع الطلبات المكررة، حالات الدفع والاسترداد، سجل إشعارات بوابة الدفع، حدود ضغط الطلبات، مواقع التوصيل، تنبيهات الأعطال وانتهاء الفترة التجريبية. مفاتيح الدفع السرية تبقى في بيئة الخادم ولا توضع في إعدادات المتصفح.

## تفعيل منصة White‑Label

الملف `20260826000200_white_label_saas.sql` يضيف المؤسسات والفروع والباقات والاشتراكات ومديري المنصة ودعوات الموظفين والنطاقات الخاصة وسجل التدقيق وحدود الباقات.

بعد إنشاء حساب مالك المنصة في Supabase Auth، فعّله مرة واحدة:

```sql
insert into public.platform_admins(user_id) values ('AUTH_USER_UUID');
```

تفتح لوحة مالك المنصة من `/platform`. في الوضع التجريبي المحلي استخدم `owner@platform.local` وكلمة المرور `12345678`.

يجب توجيه DNS للنطاقات الخاصة إلى التطبيق المنشور. بعد التحقق من الملكية غيّر حالة السجل في `custom_domains` إلى `active`، وسيوجّه جذر النطاق إلى متجر المطعم تلقائيًا.
